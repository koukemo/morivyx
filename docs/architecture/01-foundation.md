# 基盤

## 構想

Morivyx が目指す世界は、次のとおりです。

> 人間が思い描いたことを、最小限の摩擦で現実へ変換できる世界

ここでいう「現実」は、ソフトウェアの状態だけを意味しません。人間の理解、組織の意思決定、デジタル環境、物理環境、機器や空間の状態までを含みます。

Morivyx は、人間の意図を自動化へ置き換えるのではなく、人間と機械が共有できる意味、証拠、判断、実行結果を長期間維持することで、この変換を支援します。

## 使命

Morivyx の使命は、AI と人間が次の改善ループを継続的かつ検証可能に実行できる、知識と実行の基盤を構築することです。

```text
Goal
  → Intent
  → Knowledge
  → Plan
  → Implementation
  → Verification
  → Observation
  → Learning
  → Goal
```

基盤の責務は、各段階を自動化することではなく、段階間の意味的な接続、変更理由、実行主体、証拠、結果を保存し、安全な変更として循環させることです。

## 設計思想

### 意味を成果物より長生きさせる

コード、文書、図、モデル、デバイス設定は重要ですが、いずれも特定時点の表現です。Morivyx は、それらを生んだ Goal、Intent、Decision、Knowledge と、結果を示す Observation を論理 Graph として保持します。

### Graph は論理モデルであり、製品選定ではない

Graph を優先するとは、Graph 専用データベースを優先することではありません。Entity と Relation による意味構造を中心に据え、Git 上のファイル、関係データベース、Graph 専用データベース、分散保存機構などの物理表現は adapter として交換可能にします。

### Decision は履歴ではなく設計データである

最終的な結論だけでは、後から前提の変化を判断できません。Decision には、問い、文脈、代替案、選択、根拠、影響、再検討条件を保持します。採択済みの判断は上書きせず、新しい判断によって置き換えます。

### AI の出力を事実と同一視しない

生成、推論、観測、検証済みの知識を区別します。AI は変更を提案できますが、提案は ChangeSet として検証・ポリシー評価・必要な人間レビューを経てから中核 Graph に反映されます。

### 現実世界の実行ほど統制を強くする

外部 API、機器、ロボット、空間への作用は、読み取りより高い権限と明示的な承認を必要とします。自律性は Capability と Policy の範囲内で段階的に与え、停止可能性、監査可能性、可逆性を設計に含めます。

## 構造上の Invariant

技術選択が変わっても、次の不変条件を維持します。

1. すべての正規データは、型付けされた Entity と Relation として意味を復元できる。
2. 安定 ID は表示名、ファイルパス、保存形式、製品名に依存しない。
3. すべての変更は、主体、方法、時刻、入力または根拠まで追跡できる。
4. 採択済み Decision、検証結果、Observation は履歴を失う上書きをしない。
5. 生成物は、入力スナップショットと生成手段を特定できる。
6. プラグインは中核ストアを直接変更せず、検証可能な ChangeSet を提出する。
7. AI の推論結果と、人間の判断、外部からの観測、機械的な検証結果を区別する。
8. セキュリティ、プライバシー、安全性に関する境界は、意味モデルと実行モデルの両方に現れる。
9. 主要な意味変更は、機械的な migration と人間が読める Decision の両方を伴う。
10. 特定の Model、提供者、データベース、画面、プログラミング言語なしでも中核データを解釈できる。

## Core 原則

- メタモデルを優先する
- 型を持つ Graph
- 正規データと派生 View
- 人間が review できる変更
- 確信度だけでなく根拠を優先する
- Decision を明示する
- 全経路を Trace できる
- Plugin を最小権限にする
- Model と提供者に依存しない
- Domain ごとに意味を拡張できる
- Execution を取り消し可能かつ観測可能にする
- version を持つ契約で進化する

## 対象外

- 世界の全概念を事前に定義する上位オントロジー
- 一つの自律エージェントによる全工程の置き換え
- 新しい大規模言語モデル、プログラミング言語、統合開発環境、UML または SysML の代替
- 任意の生成物を正規データとして無条件に取り込むこと
- 初期段階からの分散 Graph、リアルタイム協調、物理デバイス制御
- 保存形式や Graph 専用データベースの機能を、そのまま Domain の論理モデルにすること
