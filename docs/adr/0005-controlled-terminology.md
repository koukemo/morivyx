# ADR-0005: 承認済み用語による説明の統制

## 文脈

現行文書では、Morivyx 固有の概念、外部の固有名詞、規格名、コード識別子、図表構文、英語の一般語が混在しています。同じ表記が指す範囲と、表記を使用できる場所を一つの規則から確認できないため、人間と agent が異なる意味で説明する余地があります。

日本語の一般語まで定義すると、意味の統一に必要な範囲を超えます。一方、英字表記を無条件に許可すると、未定義の概念を説明へ持ち込めます。

## 決定

説明に使う語を、次の二つへ分けます。

1. Morivyx の意味を担う用語
2. 識別子、固有名詞、規格名、構文などの参照表記

意味を担う用語には、正式表記、定義、意味に含むもの、含まないもの、許可表記、状態を記録します。参照表記には、区分、使用可能な場所、意味を確認する場所、状態を記録します。

Morivyx の説明文は、日本語の一般語と、承認済みの用語だけで書きます。参照表記は、その区分で許可された場所にだけ記載します。

用語の最終承認者は利用者本人とします。新しい用語と定義変更は、利用者が明示的に承認するまで提案中です。agent は提案中の状態を承認済みへ変更しません。

規則、用語集、表記台帳は `docs/terminology/` で管理します。人間と agent へ同じ規則を適用します。

## 結果

### 利点

- 同じ用語が指す範囲と指さない範囲を一か所で確認できます。
- 概念名とコード識別子を区別できます。
- 未定義語の混入を機械的に検出できます。
- 用語の追加と意味変更を利用者の承認対象にできます。

### 負担

- 用語を追加する前に、定義と意味の境界を提案する必要があります。
- 外部規格や識別子の追加でも表記台帳の更新が必要です。
- 既存文書を承認済み用語へ段階的に置き換える必要があります。

## 検証

- 現行 Markdown の全英字表記が、用語または参照表記として台帳に現れること。
- 説明文に未登録の英字表記を追加すると検査が失敗すること。
- 用語ごとに、意味へ含む例と含まない例を確認できること。
- 利用者の承認なしに、提案中の用語が承認済みにならないこと。

## 再検討条件

- 日本語だけの未定義語が、Morivyx 固有の意味の不一致を繰り返し生む場合。
- 一つの表記に複数の意味を認める必要が生じ、使用場所だけでは区別できない場合。
- 外部規格の用語体系を取り込むため、現在の区分では由来を保持できない場合。
